# Mechanics tables (`wf-tables`)

Crate `engine/crates/wf-tables`: reads Buu's Fury's game-mechanics tables straight from the ROM (no emulator) and
writes them as per-id JSON files. It is a port of the research extractors `re/buu/extract_*.py` (+ `ai_decode.py`,
`boss_*`, `scriptdis.py`, `vm.py`, `loot.py`, `spawns.py`, `tables.py`) and `tools/battle/gen_buu_ai_extra.py`.

    wf_tables::extract(&rom, &mut content)      // content files below
    wf_tables::build(&rom)                      // the 11 reference-shaped documents (data/buu/*.json layout)
    wf_tables::content::reassemble(get)         // content files -> the 11 documents (inverse of the split)

Native release: 1 409 files, 4.1 MB, ~0.65 s (most of it is the loot Monte-Carlo). Builds for `wasm32-unknown-unknown`.

## Content files

Paths are relative to the content root. Every per-id file starts with `"id"` (its file name); the game's own
index stays in a field (`game_id`, `skill`, `item`, `type`, `sub`, `index`). Ids are slugs of the game's names, made
unique with the game index where names repeat: forms `NN_<name>` (`03_goku`), skills `NN_<name>`
(`20_super_saiyan`), attacks `NN_<name>` (sub id), items / equipment `NNN_<name>`, enemies and bosses the slug of the
enemy's display name (`majin_buu_giant_crater_with_babidi`, `type_xx` if unnamed), AI states `state_XXX` (hex id).
Each directory has an `index.json` listing its ids in game order (plus the shared documentation of that topic).

| path | content | ROM source |
|---|---|---|
| `levels.json` | XP needed per level 50..200, `to_next` | XP table `0x086B7084` |
| `formulas.json` | damage / crit / XP / level-up / regen / loot formulas (documentation) + `level_up.growth_rows` | growth rows `0x086B72E0` |
| `rng.json` | the PRNG (`0x0803FAAC`) and its helpers | (documentation) |
| `characters/<id>.json` | new-game record, growth rows + ranges, form ids | `0x086FDA4C`, `0x086B72E0` |
| `forms/<id>.json` | form record (flags, names, gfx id, transform links), `measured_bonus` | `0x086B82EC` (54 x 24 B) |
| `moves.json` | melee hitboxes, block / energy block / dash, hit struct, ki blast, beam level defs, Big Bang | `0x083C344C`, `0x08719C40`, `0x0871DA68`, `0x0871E148`, `0x0871DDBC` |
| `skills/<id>.json` | skill record, EP cost rule + per-level costs, measured runs; `detail` = state class (vtable fns), cost, measured trials | `0x0871DAF8`, costs `0x0871DA98`, vtables |
| `attacks/<id>.json` | attack type by sub id: `type` (moves view) / `detail` (attacks view), `name` | `0x086B8088` |
| `items/<id>.json` | supply / story item, price, use script disassembly + effect, `icon` = `icons/supply/NNN.png` (def +0xC: w, h, attributes, graphic - the Use dialog's picture, 32x32 for the Large Fish and the 40 exhibit crates); those 41 also have `icons/supply/NNN_small.png` (def +0x1C.., the second picture, 16x16: the inventory list's and the field's) | `0x083BD2F8` (83 x 52 B), scripts |
| `equipment/<id>.json` | slot, required level, stat modifiers, XP bonus, price, effect script + effects, `icon` = `icons/equipment/NNN.png` | `0x086F82EC` (162 x 44 B) |
| `enemies/<id>.json` | stats, database entries, gfx defs, spawn points, drops + simulated loot, `ai_tree` (initial state, reachable states, summary), `death` node, `boss` link | `0x08711274`, `0x0874D380`, areas `0x0808E2E0`, scripts |
| `ai/<state>.json` | decoded behaviour tree (`tree` + `text`), on-hit tree (`aux`), reaction-state tree (`reaction`) | state table `0x0870F514` |
| `ai/index.json` | node types (registry + usage counts), on-hit protocol, state list | |
| `bosses/<id>.json` | phases, attacks, movement, projectiles used, ai state texts, stats | stats/AI from ROM, facts annotated |
| `bosses/index.json` | projectile classes, regular-enemy specials, node registry | |
| `text/strings.json` | the whole UTF-16 string table (index = string id, `{xxxx}` = control codes) | `0x0806BCE8` |

Units (as in the field names / research docs): time in 60 Hz frames (`_frames`, AI `frames`/`seconds`); positions
and rectangles in px relative to the entity position; speeds in 1/256 px per frame (`_256ths`, AI `speed256`,
converted `px_per_frame`); AI distances are stored squared (`dist2`, converted `px`); chances `prob16` = p/65536 per
frame (converted `percent_per_frame`, `mean_frames`); multipliers 1024 = x1.0; resists 128 = x1.0; HP/EP points;
XP bonus in 1/256. ROM addresses are kept as provenance (`address`, `*_fn`, `*_rom`, Python `hex()` spelling).

## ROM vs annotations

Everything the ROM holds is read from the ROM. What is *not* in the ROM — documentation, hand-decoded semantics,
curated names, emulator measurements — lives in `engine/crates/wf-tables/data/*.json` (embedded with
`include_str!`), generated by `re/dump_annotations.py` from the research modules (registries / constants) and,
for emulator measurements, from the measured sub-trees of `data/buu/*.json`. No ROM table value is stored there.
Status tags (`VERIFIED` / `DISASM` / `INFERRED` / `measured`) are kept as in the research output.

Fields that come from annotations:

* `levels.json`: `meta`. `rng.json`: all (algorithm documentation). `formulas.json`: all except `level_up.growth_rows`.
* characters: `meta`, `level_range`, `stat_points`, `level_up`, `movement`, `fusion`, `form_flag_bits`,
  `record_layout`; `characters[].name` (labels for the 9 record slots); the growth formula strings
  (`hp_add`, `hp_pct`, `ep_add`, `ep_pct`) and the unused-row note; the meaning of each form flag bit
  (`flag_bits` texts — which bits are set is ROM).
* forms `measured_bonus` (STR/POW/END/END_energy/walk/dash added by the form): **emulator-measured** for all 54
  forms. Not a data table: the bonuses are immediates in the ApplyRecordToPlayer variants (`0x0800E1AE`,
  `0x0800E2F2`, `0x0800E344`, `0x0800E470`, `0x0800E550`, `0x0800E5C0`) reached through the form's controller slot,
  an IWRAM object (`0x03001B60..0x03001B8C`) built at boot — the only ROM reference to a slot is a code literal
  (`0x080483C8`), so there is nothing to read without disassembling the boot constructor (`re/find_slots.py`).
* moves: `meta`, melee doc strings (`input`, `hit`, `rect_format`, `after`, `ep_gain_on_hit`, `crit`, `status`),
  `skill_levels`; per skill the EP rule text, the hand-read immediates `canuse_min_ep` / `spend` /
  `spend_per_tick` / `percent_of_max_ep`, which cost-table slice a skill uses (the slice values are ROM);
  `skills[].measured` (**emulator**).
* attacks: `melee` documentation fields and `melee.forms[]` (**emulator**: recovery frames, walk/dash speeds, melee
  anims; form names are ROM), `block`, `energy_block`, `dash`, `hit_struct`, ki blast / beam / Big Bang
  documentation fields (`charge_rate`, beam `level_defs`, velocities are ROM), per skill `kind`, fixed costs and cost
  notes, the state-class vtable address (its 5 functions are read from the ROM vtable), `skills[].measured`
  (**emulator**); `attack_sub_names` for subs 2 and 3 (the others are ROM skill names, stored as skill ids).
* items: `meta`; equipment `other_effects` (behaviour in shared scripts #2 / #497, from disassembly).
  The script disassembly and the `effect` / `script_effects` summaries are computed from the ROM bytecode by the
  same rules as the Python.
* enemies: `meta`, `stats_note`, `display_name` qualifiers / descriptive names (`display_name_source`
  `game name + qualifier` / `descriptive`), the string id used for Uub's name, hit-reaction labels, loot simulation
  parameters (20 000 kills per loot level, seed 1). Loot expectations are a Monte-Carlo of the ROM loot script
  (#497) on a Rust port of the bytecode VM with a CPython-identical Mersenne Twister, so they match exactly.
* AI: `meta` (incl. the emulator `verified` checks), the node registry (names, kinds, statuses, semantics,
  parameter layouts + units, child layouts) for 183 create functions. Trees, parameters and reachability are ROM.
* bosses: all behaviour facts (phases, attacks, timings, projectiles, specials, node timings) are annotations
  (hand analysis + emulator, tagged); `stats`, `initial_state`, `ai_states` texts and fallback names are ROM.
* on-hit (aux) trees: `source`, `onhit_protocol`, `onhit_fns`, `aux_only`, `extra_nodes`; trees and death nodes are ROM.

## Parity

`cargo test -p wf-tables` (`tests/parity.rs`) runs the extraction, rebuilds the 11 research documents from the
content files alone (`content::reassemble`) and compares them value by value (numbers by value) with
`data/buu/{levels,rng,formulas,characters,moves,attacks_detail,items,enemies,enemy_ai,bosses}.json` and
`data/battle/buu_ai_extra.json`. Result: all 11 identical, with one documented exclusion:

| file | path | count | why |
|---|---|---|---|
| `enemy_ai.json` | `enemies[132].name` | 1 | the reference was generated from an older `enemies.json` that lacked the ROM-text name "Uub" (type 0x84); `enemies.json` has it and so does our output |

The MT19937 port is unit-tested against CPython (`script::tests`).

## Regenerating annotations

    cd re/buu && ../../.venv/bin/python ../../engine/crates/wf-tables/re/dump_annotations.py [levels rng ... ai_extra]

Run it after the research modules or measured data change, then `cargo test -p wf-tables`.
