# Dragon Ball Z: Buu's Fury (USA) — mechanics reverse engineering

ROM: `roms/buu.gba`. All addresses are GBA bus addresses. Thumb function addresses are shown without the +1
unless a table stores them with it.

Tags:
- **VERIFIED** means checked against the running game (headless mGBA via `tools/emu`), or exact
  disassembly whose effect was observed.
- **INFERRED** means read from code or data but not exercised in the emulator.

Data lives in `data/buu/*.json`. Each file is regenerated by the matching `re/buu/extract_*.py`, run from
`re/buu/` with the repo venv: `../../.venv/bin/python extract_X.py`.

|---|---|---|

| levels.json | extract_levels.py | XP table, levels 50..200 |

## 1. Engine overview

- **C++ with vtables.** Vtables are tables of *self-relative* s32 entries: target = &entry_table_base + s32.
  `vtab.py entries()` decodes them. Objects are heap blocks; actor x/y are 24.8 fixed point at
  obj+0x1A0/+0x1A4 (1/256 px).
- **Text.** UTF-16 strings behind the pointer table at `0x0806BCE8` (1534 strings). `{xxxx}` marks control
  codes. Decoded by `strtab.py`.
- **Bytecode VM** (story, items, equipment effects, loot):
  - Interpreter `0x08004038`. Script runner `0x08004098(r1 = script header, r2 = params)`.
  - Opcode table `0x080554C0`, natives table `0x08055098`, setters table `0x08055478`.
  - Script table `0x0879B704`: 522 entries.
  - Blob byte 2 = 0 means raw code at +3. Byte 2 = 4 means compressed code at +4, inflated by `0x08049120`
    into IWRAM `0x03000040`.
  - Globals G0..G3 are words at `0x03001058`, *shared by nested scripts*. Params P0..P3 are reached through
    `[0x03001030]`.
  - Opcodes 0x15..0x1A take one operand byte. `pushn [...]` pushes a list of varints.
  - Tools: `scriptdis.py` (disassembler, decompression via `decomp.py`), `dump_scripts.py`
    (`work/buu/scripts_all.txt`), and `vm.py` (Python re-implementation of the natives used by loot and
    items).
- **PRNG** `0x0803FAAC`, state at `0x03004A5C`/`0x03004A60`. VERIFIED: it reproduces damage rolls,
  level-ups and loot exactly.

  ```
  a = (s0 + 0x02CBBC71) ^ s1
  b = (rol32(s1,3) + 0x0632D80F) ^ a
  s0,s1 = a,b
  return a - b
  ```

  - `rand(n)` (`0x0803FACC`) = `((next()&0xFFFF)*n)>>16`.
  - `chance(p)` (`0x0803FADE`) = `(next()&0xFFFF) < p`.
  - Script native 0x19 is `rand(n)`. Native 0x1A is `chance(n percent)`, which uses
    p = n·0x28F5D>>8.
- **Enemy AI** is a behaviour tree; see §8.
- **Teleporting for research** (`warp.py`): calling EnterArea directly freezes or crashes because it
  longjmps and needs script context. Instead, in `buu_snakeway_start.ss`:
  1. Rewrite the text-trigger object at `0x0203DFA4` (vtable `0x08049BD4`) into an exit trigger:
     vtable `0x08049BC4`, +0x10 = 2, +0x11 = 0xFF, +0x14 = pointer to exit data written at `0x0203FF40`.
  2. Fill the exit data: +8/+0xA source anchor, +0x11 world, +0x12 map, +0x14/+0x16 destination x/y.
  3. Hold RIGHT.

  Usage: `warp(e, world, map, x, y)`.
- **Calling arbitrary functions** (`emutools.call`): the BL at `0x08007052` is redirected to a stub at
  `0x082ED300` (ROM zero padding), which reads its arguments from `0x082ED400`.

## 3. Characters, levels, stats

- **Levels 50..200.** `level = 50 + max{i : XP >= T[i]}`, with T = u32[151] at `0x086B7084` and T[0] = 0
  (`0x080135D2`). XP to next = `T[L-49] - XP`. VERIFIED.
- **XP from a kill** = `(enemy.exp * rec+0x58 + 255) >> 8`, given to the active character only
  (`0x0800F80C` → `0x08013914`). Fusion forms give the full amount to both components. VERIFIED: a Majin
  Fighter gave +1225.
- **Level-up** (`0x08013678`, once per level gained). Uses the growth row g[8] of the character
  (characters.json):

  ```
  r1..r4 = rand(256) x4
  maxHP += ((g0*r1>>8) + g1) >> 16
  maxHP += maxHP * ((g2*r2>>8) + g3) >> 16
  maxEP += (g4*r3 + g5) >> 16
  maxEP += maxEP * ((g6*r4>>8) + g7) >> 16
  HP = maxHP; EP = maxEP; stat points += 3
  ```

  VERIFIED exactly (`verify_levelup.py`). Growth rows 5..8 exist in the table but no character uses them.
- **Stats do not grow automatically.** 3 points per level, each spent 1:1 on STR/POW/END/SPD on the
  Status screen. VERIFIED.
- **Stat recalculation** (`0x08013C66`), in order:
  1. Start from base stats; END is copied to both END values.
  2. Add the s8 modifiers of each of the 4 equipped items.
  3. Add each item's XP bonus to +0x58, OR its flags into +0x13, and run its effect script.
  4. Add Holy Water bonuses.
  5. Clamp at 0.
- **Applying stats to the player object** (`0x0800E074`):
  - stats are copied over and resists are set to 128
  - **walk = 5·SPD + 102** and **dash = walk + 320**, in 1/256 px per frame. VERIFIED at SPD
    10/50/100/150/255.
  - dash is a double-tap within 20 frames
- **Forms** (54 entries at `0x086B82EC`):

  | form | stat bonus | speed bonus | source |
  |---|---|---|---|
  | Super Saiyan | +5 STR/POW/END/END2 | +128 | `0x0800E2F2` |
  | SS3 | +15 | +192 | `0x0800E470` |
  | Trunks form 24 | none | speed ÷4 | |
  | Trunks form 25 | none | +64 | |

  - All 54 forms were measured in the emulator (`measure_forms.py`). VERIFIED.
  - SS gauge: filled to maxEP during the transform. Drains 1 point per 20 frames (acc += 0xCCD), so it
    lasts maxEP·20 frames. Reverts at 0. While SS, energy moves spend the gauge instead of EP.
  - SS3 gauge drains (22·maxEP + 0x3333)/65536 per frame.
  - Transforming needs rec+4 = 0. That cooldown falls by rec+0x62>>6 per frame in normal form.
  - Gauge rules VERIFIED by disassembly; SS drain of about 3 per second VERIFIED in the emulator.
- **Fusion** (`0x0801375E`). VERIFIED by disassembly.
  - HP/maxHP/EP/maxEP = (A+B)·154>>8
  - XP = (A+B)/2
  - STR/POW/END = (A+B)/2 + 10
  - SPD = (A+B)/2 + 16
- **Regen** (`0x0800E1D0`). VERIFIED (disassembly plus emulator).
  - A timer adds 110 per frame and ticks on overflow at 65536, i.e. every ~596 frames.
  - Each tick: active character EP += 3% maxEP; every reserve character gets +5% HP and +5% EP.
  - No passive HP regen, except rec+0x64/256 HP per frame ("Z" Armor: 21).
  - +1 EP per damaging melee hit (script #2).

## 4. Damage (VERIFIED: 48/48 game events reproduced exactly, `verify_damage*.py`)

`0x0800E9D8 ComputeDamage(target, hit)`. Damage is in 1/1024 HP.

```
kind = atk.byte0 (0 melee, else energy); sub = atk.byte1; power = atk.u32[+4] (1024 = 1.0)
S = attacker STR (melee) / POW (energy);  D = defender END / END2;  resist = defender +0x1B8 / +0x1B9
melee:  if sub != 3 and chance(82*S + critbonus): power += power>>1        # crit x1.5
        P = (S*power*0xCCD) >> 16                                          # S*power/20
energy: P = power
if D >= 200: D = min(D/4 + 150, 220)
X   = ((221 - D) * P * 297) >> 16
A   = S + ((S*S*(S+100)) >> 13)
Y   = (hit.mult * X + 1023) >> 10
raw = (((256 + rand(26)) * Y) >> 8) * A           # spread +0..9.8%
dmg = (resist * raw + 127) >> 7
if defender blocking and (hit.dir^1) == defender.facing: dmg = dmg * blockfactor >> 16   # 0x1000 = 1/16
HP: acc += dmg; HP -= acc>>10 (remainder carried)
```

- **Crit chance** is (82·STR + crit%·656)/65536. Equipment crit: Charge Gloves 5%, Shock Boots 10%,
  Soccer Cleats 20%.
- **I-frames:** the player hurt state lasts 24 frames, with both resist bytes 0 → damage 0. Knockback is
  about 17 px. VERIFIED in the emulator.
- **Enemy knockback** is about 15 px over 15 frames. Speed = dir·((rand(64)+96)·K)>>7, with K from the
  reaction definition (`0x08018A08`). Measured; the constants are INFERRED.
- Python model: `damage_model.py`.

### move_format: authoring a new move

1. **Attack type.** Append 8 bytes to the table at `0x086B8088`:
   - byte 0: kind (0 melee, 1 energy). Melee scales by STR/20 and can crit unless sub = 3. Energy uses
     POW and END2.
   - byte 1: a new sub id.
   - bytes 2–3: 0.
   - bytes 4–7: power as u32 (0x400 = 1.0).
2. **Skill entry.** 24 bytes in the format above. Pick a free string id for the name and description.
   Set max level to 2 for a three-level move.
3. **canUse(record)** returns non-zero if usable. The usual body is `EP >= cost` via `0x080134B8`, which
   applies the cost factor and the SS gauge.
4. **activate(record, player)** pushes a player state object with a 5-slot self-relative vtable.
5. **update.** Choose one way to hit:
   - (a) Spawn a ki blast `0x080197B4`.
   - (b) Spawn a beam `0x080206B8` with your own 16-byte level definition: w, h, mult, ?, attack sub,
     graphics, animation.
   - (c) Build a hit struct `{dir, mult, &attack_type, self}` and pass it to the target's damage
     routine, as melee does at `0x08012A24`.

   Spend EP with `0x08013504`.
6. **Damage.** Final damage follows §4. Here `hit.mult` is your per-hit multiplier, and `power` comes
   from the attack type.
7. **Learning the move.** Add its id to rec+0x0D.. and bump rec+0x0C. In the game this happens from
   story scripts.

## 7. Loot (VERIFIED)

Each enemy's drop script is `run_script(497, loot_level, forced_item)` (script #497).

1. 1% chance of no drop.
2. Otherwise roll d100 to get the number of rolls: 8 (≤5), 7 (≤10), 6 (≤20), 5 (≤30), 4 (≤40), 3 (≤55),
   2 (≤75), else 1.
   - Luck items change the count: Lucky Charm +2, Rabbit's Foot +2, Four-Leaf Clover +3, Skull Ring −1,
     Doom Amulet −2, Hare's Foot −3.
   - Clamp to 1..8.
3. **Forced item:** with a 5% chance, if the player doesn't own it, drop the forced equipment. This uses
   one roll. Example: Majin Fighter → Green Belt (132).
4. **Each roll:**
   - **Coin** if chance(85%), or if G2 and G1 are both set. The coin size comes from script #500, with
     G = (level−48)·100 and r = rand(400): 100Z if r ≤ G/100, 50Z if r ≤ G/83, 25Z if r ≤ G/66, else 5Z.
   - **Equipment** otherwise, if G1 is unset, with 25% chance. Uses script #496 (level-window tables). If
     it produces nothing, it becomes a supply roll.
   - **Supply** otherwise (script #499).
5. **Quirk:** G0..G3 are shared with the sub-scripts, and script #500 leaves G1/G2 non-zero. So after the
   first coin, every later roll is a coin as well. Items come almost only from the first roll(s).

Evidence:
- `verify_loot.py`: 500 real kills gave 3.05 coins, 0.114 supplies and 0.084 equipment per kill. The
  simulation (`loot.py`) gives 3.11, 0.109 and 0.080.
- `verify_loot2.py` replays the game's RNG state through `vm.py`: 60/60 kills exactly reproduced.
  - This needed one extra detail: spawning a pickup consumes RNG for its scatter motion. A coin costs 5
    draws and an equipment drop 4 (traced in `t_loot4.py`). A supply drop is assumed to cost 5; INFERRED.

## 8. Enemies and AI

**Enemy table** `0x08711274` (150 types). Fields:
- XP and max HP
- initial AI state id
- STR/POW/END and resists

- drop script pointer

Names come from the bestiary database link, or failing that a matching graphics id; unnamed variants are

### Behaviour trees (enemy_ai.json via extract_ai.py / ai_decode.py)

**How it works.**
- Each enemy type's entry at `0x08711274` (28 bytes per type) holds its initial AI state at +0x08.
- The state table at `0x0870F514` holds the root node of each state's behaviour tree (8 bytes per state).
- The enemy keeps an AI stack at obj+0x238 and runs the top state's tree once per frame. An update
  returning 0 means "still running"; nonzero means "finished".
- State changes:
  - GotoState replaces the top state through `0x0800AA4A` (enemy vfunc +0x68).
  - PushState pushes a state (vfunc +0x6C).
  - SubState runs another state's tree in place.

**Nodes.**
- A node is a ROM word array: `[create_fn, f1, f2, params from +0xC…, child pointers]`.
- Its runtime vtable slots are: 0 enter, 1 update, 2 exit, 5 condition.
- All conditional decorators share enter `0x080342A9`, update `0x080342AF` and exit `0x08034307`. The
  child runs only while the condition holds.

**Attacks.**
- Attack nodes switch the movement controller (obj+0x14) through `0x0800ED18` to a shared IWRAM object.
- That controller counts frames at obj+0x12, sets the animation (`0x0800ECDA`) and spawns objects
  (`0x0801191A`).
- The action ends when the enemy leaves that controller.

**Units:**

| parameter | unit |
|---|---|
| distance | squared pixels (radius = √p) |
| speed | 1/256 px per frame |
| chance | p/65536 per frame |
| time | frames |

**Coverage.** 732 reachable states and 178 node types. The hand-decoded types are 96% of all node uses;
the 128 rare boss-only types carry automatic analysis plus raw words.

**Composites.** The child count is at +0xC and the children start at +0x10.

| node | create fn |
|---|---|
| Sequence | `08018F91` |
| ParallelAll | `080191C7` |
| ParallelAny | `080191E9` |
| Selector (priority list) | `0801920F` |

**Transitions:**

| node | create fn |
|---|---|
| GotoState(state) | `0801890B` |
| SubState(state) | `08019285` |
| PushState(state) | `08018877` |

**Conditions:**

| node | create fn | notes |

**Worked examples:**
- **Majin Fighter** (Pui Pui and Spopovich run the same generic fighter tree):
  - Idles until the player is within 100 px.
  - Then runs a priority list:
    1. melee roll at 12% per frame when in range
    2. StepToward at 4% per frame inside 70 px
    3. Chase at 8% per frame beyond 90 px
    4. back off at 0.8% per frame
    5. otherwise stand and face the player
  - Each punch is followed by an 18-frame Wait.
- **Gunman:**
  - Aggro at 88 px.
  - Shot state `0xF4`: align with the player, Wait 30, GunShot.
  - Shots have a 300-frame cooldown; after 6 shots it switches to state `0x5B`.
  - It also melees at close range.
- **Yakon:**
  - Starts wandering immediately (no aggro radius).
  - Combo state `0x322`: six MeleeAttacks with a 1.40 px/frame chase between each, then Wait 60.
